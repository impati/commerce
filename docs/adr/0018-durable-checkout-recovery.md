# ADR-0018: 체크아웃 진행 상태를 저장하고 API 실행을 워커가 복구한다

- **상태:** 승인됨
- **날짜:** 2026-09-11
- **해결한 백로그:** BL-0057 체크아웃이 중단되면 진행 상태를 잃어 복구하지 못한다
- **대체:** [ADR-0009](0009-reconcile-unconfirmed-payments.md) 결제 미확인 주문을 점유 임차로 정리한다

## 맥락과 의도

기존 체크아웃은 외부 처리 결과를 주문에 붙이기 전 프로세스가 종료되면 진행 상태를 잃는다. 기존 결제 정리기는 매입 결과 불명으로 표시한 취소 주문만 처리하므로, 보상 중단과 매입 후 주문·재고 확정 중단을 복구하지 못한다.

## 결정

- 주문 DB에 주문과 분리된 체크아웃 진행 레코드를 둔다. 멱등 키, 요청 지문, 구매 입력, 현재 단계, 외부 자원 식별자, 고객 결과, 실패 코드, 다음 시도 시각과 임차 세대를 저장한다.
- API가 새 체크아웃의 정상 경로를 즉시 실행한다. API가 종단 상태를 만들지 못하면 워커가 같은 진행 레코드를 점유해 보상 또는 전진 복구한다.
- 점유는 만료 시각과 증가하는 임차 세대를 사용한다. 상태 저장은 점유 시 받은 세대를 조건으로 갱신해 만료된 실행자가 새 실행자의 결과를 덮어쓰지 못하게 한다.
- 외부 생성 명령은 주문 식별자를 멱등 키로 사용한다. 성공 뒤 진행 저장이 실패해도 같은 명령을 다시 보내 기존 결과를 회수할 수 있다.
- 매입 전 실패는 저장된 단계에서 역순 보상하고, 매입 확인 뒤에는 주문 확정과 재고 확정을 앞으로 진행한다.
- 기존 결제 미확인 정리기는 새 복구 실행기에 흡수한다. 기존 미확인 주문은 배포 마이그레이션으로 새 진행 레코드를 갖게 한다.
- 자동 진행이 안전하지 않은 오류는 운영 확인 포트에 전달한다. 첫 어댑터는 구조화 로그다.

## 고려한 선택지

- **워커가 처음부터 모든 체크아웃을 실행:** 실행 경로는 하나가 되지만 정상 요청도 큐 지연과 폴링을 거친다. 사용자가 정상 응답을 기다리는 현재 흐름을 유지하기 위해 채택하지 않았다.
- **주문 상태만 단계로 확장:** 고객 주문 생애주기와 내부 복구 상태가 결합되어 내부 단계가 외부 계약이 된다. 별도 진행 레코드를 택했다.
- **외부 성공 뒤에만 결과 저장:** 성공과 저장 사이의 중단 구간이 그대로 남는다. 멱등 명령과 단계 저장을 함께 사용한다.
- **임차 만료 시각만 사용:** 만료된 실행자가 늦게 돌아와 새 결과를 덮어쓸 수 있다. 임차 세대로 쓰기를 차단한다.
- **범용 워크플로 엔진:** 현재 체크아웃 하나보다 운영 대상과 개념이 커지므로 도입하지 않는다.

## 범위

- **포함:** 체크아웃 멱등 접수, 장바구니 구매분 분리, 단계 저장, API 실행, 워커 복구, 보상, 매입 후 전진 복구, 고객 결과 조회, 운영 신호와 기존 결제 미확인 이관.
- **제외:** 범용 워크플로 엔진, 장바구니 복원, SSE, 재고 예약 만료와 자동 복구 포기 상한.

## 완료 기준

- 단계별 중단 뒤 재실행해 주문 하나와 외부 자원 한 벌로 끝난다.
- 같은 멱등 키의 중복·동시 요청과 API·워커 동시 실행이 결과를 중복하지 않는다.
- 매입 전 실패는 보상되고 매입 확인 뒤 실패는 성공으로 전진 복구된다.
- 주문 조회가 고객 결과와 결제 정리 상태를 제공하며 내부 오류는 노출하지 않는다.

## 위임된 결정

테이블과 클래스 이름, 임차·주기·배치 설정값, 마이그레이션 순서와 테스트 배치는 저장소의 기존 조건부 UPDATE·`Clock`·모듈 분리 패턴을 따른다.

## 결과와 제약

외부 호출과 DB 저장을 원자적으로 만들지 않아도 중단 지점을 다시 찾고 같은 명령으로 결과를 회수할 수 있다. 대신 각 협력 서비스가 주문 식별자 기준의 멱등성과 반복 가능한 종단 명령을 지켜야 한다.
