# ADR-0020: 브라우저 세션은 HttpOnly 쿠키로 운반한다

- **상태:** 승인됨
- **날짜:** 2026-09-14

## 맥락과 의도

storefront가 14일 동안 유효한 세션 토큰과 5분 동안 유효한 접근 토큰을 `localStorage`에 보관한다.
페이지에서 실행되는 JavaScript는 이 저장소를 읽을 수 있으므로 XSS가 생기면 장기 세션 토큰을 다른
기기로 빼내 다시 사용할 수 있다.

## 결정

게이트웨이는 로그인 성공 시 세션 토큰을 응답 본문에서 제거하고 host-only `HttpOnly` 쿠키로
설정한다. 쿠키에는 `Secure`, `SameSite=Strict`, `Path=/`를 적용하고 서버 세션 만료 시각을
`Max-Age`에 반영한다. 갱신과 로그아웃은 이 쿠키에서만 세션 토큰을 읽는다. 비브라우저 호출도
쿠키 저장소를 사용해 같은 계약을 따른다.

접근 토큰은 storefront의 JavaScript 메모리에만 둔다. 페이지를 새로 열면 저장된 접근 토큰이 없으므로
세션 쿠키로 새 접근 토큰을 발급받은 뒤 로그인 상태를 복원한다. 이전 버전이 남긴 두 토큰은 시작할
때 `localStorage`에서 삭제한다.

쿠키를 설정하거나 사용하는 로그인·갱신·로그아웃 요청은 `Origin`이 있으면 설정된 브라우저 origin과
일치하는지 확인한다. 브라우저의 cross-site 요청은 origin 검사와 `SameSite=Strict`가 막는다.
`Origin`이 없는 서버·CLI 호출은 쿠키 저장소를 사용해 호출할 수 있다.

## 고려한 선택지

접근 토큰을 `localStorage`에 남기는 방식은 채택하지 않는다. 수명이 짧아 세션 토큰보다 피해는 작지만
페이지를 새로 열 때 쿠키로 즉시 재발급할 수 있으므로 영속 저장할 이유가 없다.

세션 토큰과 접근 토큰을 모두 쿠키로 보내는 방식은 채택하지 않는다. 그러면 모든 변경 요청이 쿠키
인증을 사용해 CSRF 방어 범위가 전체 API로 넓어진다. 짧은 접근 토큰을 명시적인 헤더로 보내면
쿠키 인증 경로를 로그인·갱신·로그아웃으로 제한할 수 있다.

## 범위

- **포함:** 게이트웨이 세션 쿠키 발급·읽기·삭제, 브라우저 origin 검사, 로그인 외부 응답 변경,
  storefront 토큰 저장소 제거와 새로고침 복원, 관련 테스트와 사용 문서
- **제외:** XSS 원인 자체의 탐지·제거, 서버 세션 수명과 폐기 정책 변경, 전체 API의 쿠키 인증 전환

## 완료 기준

- 로그인 응답 본문에 세션 토큰이 없고 `HttpOnly` 세션 쿠키가 설정된다.
- storefront의 `localStorage`에 세션 토큰과 접근 토큰이 남지 않는다.
- 페이지를 새로 열어도 유효한 세션 쿠키로 로그인 상태가 복원된다.
- 허용되지 않은 browser origin의 로그인·갱신·로그아웃이 거절된다.
- 로그아웃은 서버 세션을 폐기하고 브라우저 쿠키를 삭제한다.
- `make verify`와 프론트엔드 빌드가 통과한다.

## 위임된 결정

쿠키 이름, 지원 코드의 클래스와 메서드 이름, 테스트 이름은 기존 명명 규칙을 따른다. 운영 환경은
허용 origin과 `Secure` 사용 여부를 환경 변수로 명시할 수 있고, 기본값은 로컬 storefront와
`Secure=true`로 둔다.

## 결과와 제약

XSS가 생겨도 스크립트가 장기 세션 토큰 값을 직접 읽어 외부에서 재사용할 수 없다. 실행 중인 페이지의
짧은 접근 토큰과 사용자 권한으로 요청을 보내는 능력까지 없애는 것은 아니므로 XSS 방어 자체는 계속
필요하다. 비브라우저 클라이언트도 장기 세션이 필요하면 쿠키 저장소를 사용해야 한다.
