# ADR-0024: 확인한 장바구니 버전으로 줄을 수정한다

- **상태:** 승인됨
- **날짜:** 2026-09-17

## 맥락과 의도

장바구니에는 추가만 가능하고 줄별 수량 변경과 삭제가 없다. 오래된 화면의 수정이 다른 탭의 변경을 덮어쓰지 않으며, 사용자가 적용한 구매 내용과 견적을 확인한 뒤 주문할 수 있어야 한다.

## 결정

- 제거, +, −, 수량 입력을 제공한다. 수량은 1 이상이며 1에서는 −를 비활성화한다. +와 −는 즉시 반영하고 입력은 Enter 또는 적용 버튼으로 확정한다.
- 변경과 삭제는 화면에서 조회한 예상 버전을 전달한다. 현재 버전과 정확히 같아야 허용하며 기존 저장 시점의 조건부 갱신도 유지한다. 충돌에서는 최신 장바구니를 표시하고 재조작을 요구한다.
- 같은 수량은 성공으로 응답하되 버전을 유지한다. 없는 줄의 변경과 삭제는 거절한다.
- 미적용 입력이 있으면 결제를 제한한다. 변경 요청과 후속 조회가 끝날 때까지 장바구니 조작과 결제를 제한한다.
- 저장 성공과 후속 조회 실패를 구분한다. 저장 여부가 불명확한 요청은 자동 반복하지 않고 조회만 다시 시도한다.
- 기존 견적 재계산, 구매분 분리와 주문 멱등성을 유지한다. 변경과 주문이 경합해도 오래된 구매 내용이 결제로 진행하지 못하도록 검증한다.

## 고려한 선택지

- 수량 0을 삭제로 해석하는 방식 대신 별도 제거 버튼을 택해 입력 실수로 삭제되는 일을 막는다.
- 입력 중간값의 즉시 저장 대신 명시적 적용을 택한다.
- 최신 상태에 오래된 수정의 자동 재적용 대신 거절과 재확인을 택해 다른 변경을 덮어쓰지 않는다.
- 프론트의 버튼 제한과 서버의 버전·견적 검증을 함께 적용한다.

## 범위

- **포함:** cart-service, Storefront BFF, Gateway, 프론트 화면과 관련 테스트.
- **제외:** 전체 비우기 UI, 삭제 복구, 일부 상품만 결제, I/O 실행 모델 변경.

## 완료 기준

정상 수정과 삭제, 잘못된 수량, 오래된 버전, 같은 수량, 없는 줄, 변경과 주문의 경합, 실패 표시와 결제 제한을 검증한다. `make verify`, `make frontend-test`, `make frontend-build`가 통과해야 한다.

## 위임된 결정

API 경로·HTTP 메서드, 오류 문구, 컴포넌트 구성은 기존 규약과 가독성을 기준으로 결정한다.

## 결과와 제약

장바구니 전체 버전을 사용하므로 다른 줄의 변경도 충돌로 처리한다. 버전은 오래된 요청을 감지하는 수단이며 인증·소유권 확인과 서버 입력 검증을 대체하지 않는다. 완료 백로그 이동은 코드 리뷰 이후에 한다.
