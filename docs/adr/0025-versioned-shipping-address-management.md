# ADR-0025: 주소록 버전으로 관리하고 확인한 배송 정보로 주문한다

- **상태:** 승인됨
- **날짜:** 2026-09-18

## 맥락과 의도

배송지는 추가·조회만 가능하다. 고객이 배송지를 관리하고 주문에 선택하며, 오래된 화면이 최신 주소록을 덮어쓰거나 확인하지 않은 주소로 주문하지 않도록 한다. 서비스 규칙은 PD-0022로 기록한다.

## 결정

- 관리 요청은 추가를 포함해 조회한 주소록 전체 버전을 전달한다. 저장 시점에도 조건부 갱신으로 검사하고 주소록과 버전 증가를 같은 트랜잭션에 저장한다.
- 회원 인증 상태 저장은 주소록을 덮어쓰지 않는다. 배송지 저장은 주소록 버전과 주소만 바꿔 서로의 변경을 유실하지 않는다.
- 주문 요청은 선택한 배송지 식별자와 실제 배송 정보의 확인값을 전달한다. 주문 서버는 회원의 최신 배송 정보를 조회해 확인값을 비교하고, 일치한 조회 결과를 주문 사본으로 고정한다. 조회 후 변경은 이미 확인한 사본을 바꾸지 않는다.
- 확인값에는 배송지 식별자·수령인·전화번호·주소·도시·우편번호만 포함한다. 별칭·기본 지정·다른 배송지 변경은 재확인을 유발하지 않는다.
- 같은 주문 요청의 재시도는 최신 주소록 검증보다 먼저 기존 접수 결과를 확인한다. 원래 배송지 식별자·확인값도 주문 멱등 요청 지문과 클라이언트 복구 정보에 보존한다.
- 별도 관리 화면에서 추가·수정·삭제·기본 지정을 제공하고 주문 화면에서는 배송지 선택과 확인 및 관리 화면 이동을 제공한다.
- 결과 불명확 시 변경을 반복하지 않고 조회로 확인한다. 최신 조회가 완료되기 전 조작과 새 주문을 제한한다.
- 관리 화면에서 주소록 버전 변경을 확인하면 편집 대상을 세밀하게 병합하지 않고 작성 중인 입력을 서버 최신 값으로 초기화한다. 편집 대상이 삭제됐으면 편집을 종료한다.

## 고려한 선택지

- 배송지별 관리 버전 대신 주소록 전체 버전을 선택해 기본 지정과 삭제를 함께 조정한다.
- 최신 주소로 묵시적 주문 대신 실제 배송 정보 비교와 재확인을 선택한다.
- 주문 화면에 모든 편집을 모으는 대신 별도 관리 화면을 선택한다.

## 범위

- **포함:** 회원 서비스, Gateway, Storefront BFF, 주문 접수 계약과 프론트 화면 및 관련 테스트.
- **제외:** 외부 주소 검색·우편번호 조회 연동 (BL-0084), 주문 접수 후 배송지 변경.

## 완료 기준

배송지 관리·기본 지정·소유권·버전 충돌·중복 추가, 주문 배송 정보 확인과 접수 후 사본 보존, 통신 실패 복구를 검증한다. `make verify`, `make frontend-test`, `make frontend-build`가 통과해야 한다.

## 위임된 결정

API 경로, 오류 문구, 컴포넌트와 내부 타입 구성은 기존 규약과 가독성을 따른다.

## 결과와 제약

서로 다른 배송지의 관리도 주소록 버전 충돌이 될 수 있다. 배송 정보 확인값은 변경 감지용이며 소유권 검사를 대체하지 않는다. 회원 서비스에서 읽은 배송 정보가 주문 사본이며 서비스 사이에 분산 트랜잭션을 도입하지 않는다. 백로그는 코드 리뷰 후 완료한다.
