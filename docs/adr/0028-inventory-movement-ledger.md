# ADR-0028: 현재 재고와 이동 원장을 함께 유지한다

- **상태:** 승인됨
- **날짜:** 2026-09-21

## 맥락과 의도

재고 서비스는 SKU별 보유 수량과 예약 수량의 현재값만 저장한다. 입고, 주문 예약, 판매 확정, 예약 해제와 고객 주문 취소가 수량을 바꾸지만 어떤 재고 사실이 언제 얼마만큼 반영됐는지는 남지 않는다. 예약의 최종 상태와 주문 식별자로 일부 결과를 추적할 수는 있어도 여러 변화가 누적된 현재 수량을 설명할 수는 없다.

재고 현재값의 빠른 조회와 동시성 제어는 유지하면서, 실제로 적용된 모든 변화를 원인과 관련 업무 식별자에 연결된 불변 이력으로 남긴다.

## 결정

- `stock_items`를 보유 수량과 예약 수량 현재값의 정본으로 유지한다. 이동 이력을 재생해 현재값을 계산하는 이벤트 소싱은 도입하지 않는다.
- 현재값을 바꾸는 트랜잭션이 append-only 이동 원장도 함께 기록한다. 어느 한쪽 저장이 실패하면 현재값, 예약 상태와 이력을 모두 롤백한다.
- 한 업무 사건을 이동 헤더 하나로 기록하고, 사건에 포함된 SKU별 변화를 품목 줄로 기록한다. 다품목 예약·확정·해제·복원도 하나의 사건으로 보존한다.
- 각 품목 줄에는 보유 수량과 예약 수량의 증감량 및 반영 후 잔액을 함께 저장한다. 반영 전 잔액은 반영 후 잔액에서 증감량을 빼서 구할 수 있다.
- 이동 원인은 재고 서비스가 직접 확인한 `STOCK_INCREASED`, `RESERVATION_CREATED`, `RESERVATION_COMMITTED`, `RESERVATION_RELEASED`, `RESERVATION_RESTORED`로 제한한다. 예약 관련 이동에는 주문과 예약 식별자를 함께 기록한다.
- 상태 변화가 처음 적용된 경우에만 이동을 기록한다. 멱등 재시도로 변화가 없거나 요청이 실패한 경우는 이동 원장에 남기지 않는다.
- 운영 데이터가 없으므로 기존 수량을 위한 기초 잔액이나 데이터 백필을 만들지 않는다. 이력 도입 뒤 생성되는 재고부터 원장으로 설명한다.

## 고려한 선택지

- 보유 수량 변화만 기록하면 예약과 해제로 바뀌는 판매 가능 수량을 설명할 수 없어 제외했다. 보유 수량과 예약 수량의 증감을 같은 품목 줄에 기록한다.
- SKU마다 독립된 이동 행을 만들면 다품목 예약 한 건이 여러 사건처럼 보이고 다시 묶을 상관관계 식별자가 필요해진다. 헤더와 품목 줄을 분리해 한 업무 사건을 그대로 보존한다.
- 증감량만 저장하면 특정 시점의 잔액과 현재값 불일치 지점을 확인하려고 전체 원장을 매번 합산해야 한다. 같은 트랜잭션에서 반영 후 잔액도 함께 고정한다.
- 주문 서비스의 `CHECKOUT_FAILED`나 `CUSTOMER_ORDER_CANCELLED` 같은 원인을 받으면 의미는 풍부하지만 재고 원장이 호출자의 워크플로 언어와 입력 정확성에 의존한다. 재고 서비스가 확정한 사실만 원인으로 기록하고 관련 업무는 주문과 예약 식별자로 연결한다.
- 실패와 중복 시도를 수량 0인 이동으로 남기면 재고 원장과 실행 감사 로그의 역할이 섞인다. 호출 감사가 필요하면 별도 감사 기능으로 다룬다.

## 범위

- **포함:** 이동 헤더와 품목 줄의 도메인·영속화 모델, 현재 다섯 재고 변화의 원자적 기록, 증감량과 반영 후 잔액, 주문·예약 참조, 동시성·멱등성·롤백 검증.
- **제외:** 이동 조회 API와 운영 화면, WMS와 백오피스, 반품·파손·분실·수동 조정, 재고 증가용 업무 식별자와 멱등성 변경, 기존 데이터 백필, 이벤트 소싱.

## 완료 기준

- 현재 다섯 재고 변화가 각각 정확한 이동 원인, 시각, 관련 식별자, 증감량과 반영 후 잔액을 남긴다.
- 다품목 변화는 헤더 하나와 품목 줄 여러 개로 기록된다.
- 현재값, 예약 상태와 이동 원장은 같은 트랜잭션으로 커밋되거나 롤백된다.
- 실패한 요청과 이미 적용된 전이의 반복 요청은 이동을 만들지 않는다.
- 동시 확정·해제·복원에서도 실제 변화와 이동이 정확히 한 번만 생성된다.
- Inventory 서비스 집중 테스트와 저장소 전체 백엔드 테스트가 통과한다.

## 위임된 결정

이동과 컬럼의 세부 이름, 식별자 생성, 시각 주입, 인덱스, 도메인·영속화 매퍼 및 테스트 배치는 기존 저장소 관례를 따른다. 구현과 그 동작을 증명하는 테스트는 같은 기능 커밋에 둔다.

## 결과와 제약

현재값 조회와 행 잠금 구조를 유지하면서 각 변화의 결과를 독립적으로 감사할 수 있다. 현재값과 원장을 중복 저장하므로 모든 쓰기 경로가 한 트랜잭션에서 둘을 함께 기록해야 한다. 원장은 내부 API로 노출하지 않으므로 운영 조회 요구가 구체화되면 검색 기준과 페이지 계약을 별도로 설계해야 한다.
