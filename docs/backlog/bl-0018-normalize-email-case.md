# 이메일을 정규화해 대소문자 구분을 없앤다

- **ID:** BL-0018
- **기록일:** 2026-08-17

## 배경

이메일 유일성이 대소문자를 구분한다 ([PD-0001-R3](../policy/pd-0001-signup-and-email-verification.md)). `Hong@impati.dev`와 `hong@impati.dev`가 별개 계정이 되고, 대문자로 가입한 사용자가 소문자로 로그인하면 실패한다. 조회 경로가 저장된 문자열을 그대로 비교하기 때문이다.

기존 근거는 두 가지다. 두 주소가 같은 사서함인지는 수신 도메인이 정하므로 발신 측에서 단정하지 않는다는 것, 그리고 중복 계정 위험은 소유 확인으로 막는다는 것이다. 앞의 논거는 규격상 옳다 — 로컬파트의 대소문자 구분은 수신 측 재량이고, 접어버리면 실제로 구분되는 사서함의 주인이 가입하지 못한다.

문제는 뒤의 논거다. 소유 확인은 **같은 사람이 자기 메일함으로 두 계정을 만드는 것**을 막지 못한다. 두 주소 모두 본인에게 도달하므로 확인 메일이 정상적으로 처리된다.

따라서 이 항목은 "기존 결정이 틀렸다"가 아니라 **어느 쪽 위험을 감수할지의 교환**이다. 접지 않으면 로그인 실패와 중복 계정을 감수하고, 접으면 대소문자를 실제로 구분하는 사서함의 주인을 잃는다. 후자를 실제로 구분하는 주요 메일 제공자는 사실상 없고, 사용자는 자신이 가입할 때 대문자를 썼는지 기억하지 못한다. 판단 근거로 쓸 관측치(중복 계정 발생 여부, 로그인 실패 문의)를 확인하는 것이 작업의 일부다.

## 목표

같은 메일함을 가리키는 주소가 하나의 계정으로만 존재한다. 가입·로그인·조회가 동일하게 정규화된 값을 사용하고, 이미 저장된 데이터의 이행 방법까지 정한다.

규칙이 바뀌므로 PD-0001을 수정하지 않고 새 정책 문서로 대체한다.
