# 비밀번호 길이 상한을 둔다

- **ID:** BL-0020
- **기록일:** 2026-08-17

## 배경

비밀번호에 최소 길이만 있고 상한이 없다 ([PD-0001-R4](../policy/pd-0001-signup-and-email-verification.md)). 해싱은 `BCryptPasswordEncoder`가 맡는데, BCrypt는 입력의 앞 72바이트만 사용하고 나머지를 조용히 버린다.

결과적으로 72바이트를 넘는 비밀번호는 뒷부분이 검증에 쓰이지 않는다. 사용자는 100자를 입력했다고 믿지만 실제로 확인되는 것은 앞 72바이트이고, 앞부분이 같은 다른 비밀번호로도 로그인된다. 오류도 경고도 없다.

한글은 UTF-8에서 한 글자가 3바이트이므로 24자 남짓에서 한계에 닿는다. 문자 수가 아니라 바이트 수가 기준이라는 점도 드러나 있지 않다.

관련 항목으로 [BL-0007](bl-0007-password-policy-to-domain.md)이 있다. 그쪽은 규칙이 어느 계층에 있어야 하는가의 문제이고, 이 항목은 규칙 자체가 빠져 있다는 문제다. 함께 처리해도 되고 나눠도 된다.

## 목표

잘려서 무시되는 입력이 존재하지 않는다. 상한을 명시적으로 정해 초과 입력을 거절하거나, 자르지 않는 해싱 방식으로 바꾼다. 어느 쪽이든 경계값을 고정하는 테스트를 둔다.

규칙이 바뀌므로 PD-0001을 수정하지 않고 새 정책 문서로 대체한다.
