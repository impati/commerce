# PD-0001의 검증 공백을 메운다

- **ID:** BL-0021
- **기록일:** 2026-08-17

## 배경

[PD-0001](../policy/pd-0001-signup-and-email-verification.md)의 규칙 10개 중 5개를 아무 테스트도 고정하지 않는다. R2(중복 이메일 거절), R4(최소 길이), R5(이메일 형식), R8(재발송 시 이전 토큰 유지), R9(발송 실패 시 가입 유지)가 그렇다.

고정되지 않은 규칙은 코드를 반대로 바꿔도 `make verify`가 통과한다. 정책 문서에 적혀 있어도 실제로 강제되는 것은 없으므로, 문서와 동작이 어긋나도 아무도 알아채지 못한다.

R3(대소문자 구분)과 R7(같은 응답으로 거절)은 부분적으로만 고정돼 있다. R3은 저장소 조회 수준만 확인하고 가입 거절 경로는 확인하지 않는다. R7은 두 테스트가 각각 같은 문구를 확인할 뿐 두 응답이 서로 같은지 비교하지 않아, 한쪽 문구만 바뀌면 통과한다.

## 목표

PD-0001의 각 규칙에 그것을 고정하는 테스트가 하나씩 대응한다. 각 테스트 주석에 규칙 ID를 남겨 정책 문서와 이어지고, 정책 문서의 검증 표에 `없음(검증 공백)`이 남지 않는다.

[BL-0018](bl-0018-normalize-email-case.md), [BL-0019](bl-0019-invalidate-previous-verification-token.md), [BL-0020](bl-0020-password-length-upper-bound.md)이 규칙 자체를 바꾸므로, 그 항목들을 먼저 처리하면 여기서 만들 테스트가 줄어든다.
