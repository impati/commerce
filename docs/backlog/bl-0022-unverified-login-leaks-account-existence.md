# 미인증 계정 로그인 응답이 계정 존재를 드러낸다

- **ID:** BL-0022
- **기록일:** 2026-08-17

## 배경

로그인 거절 응답은 등록되지 않은 이메일과 비밀번호 불일치를 구분하지 않는다 ([PD-0002-R1](../policy/pd-0002-login-rejection-and-session-lifetime.md)). 구분해서 알려주면 어떤 이메일이 가입돼 있는지 열거할 수 있기 때문이다.

그런데 소유 확인을 마치지 않은 계정만 다른 응답을 받는다 ([PD-0002-R2](../policy/pd-0002-login-rejection-and-session-lifetime.md)). 확인이 필요하다는 응답이 오면 그 이메일이 가입돼 있다는 뜻이므로, R1이 막으려던 열거가 이 경로로 성립한다.

가입 경로도 이미 중복 이메일을 명시적으로 거절하므로([PD-0001-R2](../policy/pd-0001-signup-and-email-verification.md)) 열거 통로가 하나 더 있다. 다만 그쪽은 UX를 위해 감수하기로 한 것이고, 이쪽은 같은 문서 안에서 R1과 R2가 서로 어긋나는 상태다.

미인증 계정만 노출된다는 점이 특히 나쁘다. 확인 메일을 아직 처리하지 않은 사용자는 계정을 만든 지 얼마 되지 않았다는 뜻이므로, 표적을 고르는 쪽에서는 더 값진 정보다.

## 목표

로그인 경로에서 계정의 존재 여부가 드러나지 않는다. 미인증 사용자가 자기 상태를 알 방법은 남기되, 그 방법이 인증되지 않은 요청자에게 열려 있지 않다.

규칙이 바뀌므로 PD-0002를 수정하지 않고 새 정책 문서로 대체한다. 미인증 사용자가 확인 메일을 다시 받는 경로를 어떻게 열어둘지가 함께 정해져야 한다 — 지금은 재발송이 로그인된 세션을 요구하는데, 로그인할 수 없는 사용자가 그 경로를 쓸 수 없다.
