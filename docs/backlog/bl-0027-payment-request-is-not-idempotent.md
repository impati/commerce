# 결제 요청이 멱등하지 않다

- **ID:** BL-0027
- **기록일:** 2026-08-17

## 배경

같은 주문으로 결제를 여러 번 요청하면 그때마다 새 결제가 확정된다 ([PD-0008-R5](../policy/pd-0008-payment-capture.md)). 이전 요청과 같은 요청인지 확인하지 않는다.

체크아웃 호출에는 읽기 타임아웃이 걸려 있으므로, 결제 서비스가 느리면 호출자는 실패로 판단하고 상대는 결제를 확정한 상태가 된다. 사용자가 다시 시도하면 결제가 두 건 만들어진다.

확정된 결제를 취소할 수단이 없으므로([PD-0008-R4](../policy/pd-0008-payment-capture.md)) 중복 결제는 되돌릴 수 없다. 실제 결제 대행사를 붙이면 이 지점이 곧 이중 청구가 된다.

## 목표

같은 요청이 여러 번 도착해도 결제는 한 번만 확정된다. 두 번째 요청은 새 결제를 만들지 않고 첫 번째 결과를 돌려준다. 무엇을 같은 요청으로 볼 것인지의 기준이 정해져 있다.

규칙이 바뀌므로 PD-0008을 수정하지 않고 새 정책 문서로 대체한다. 실제 대행사의 멱등 키 규격이 이 결정을 제약하므로 함께 확인한다.
