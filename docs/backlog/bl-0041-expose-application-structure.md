# 응용 계층의 구조가 패키지에 드러나지 않는다

- **ID:** BL-0041
- **기록일:** 2026-08-22

## 배경

`application` 패키지에 성격이 다른 네 종류가 평평하게 섞여 있다. 유스케이스, 출력 포트, 매퍼, 그리고 있어서는 안 되는 구동자다. 구분되는 것은 접미사뿐이라 `Service`로 끝나지 않는 파일은 열어봐야 무엇인지 안다.

```
application/
  PaymentService.java       유스케이스
  PaymentRepository.java    출력 포트
  PaymentGateway.java       출력 포트
  PaymentMapper.java        매퍼
```

두 가지가 가려진다.

- **유스케이스 목록이 드러나지 않는다.** 무엇을 할 수 있는 서비스인지 알려면 클래스를 열어 메서드를 세어야 한다.
- **각 유스케이스가 무엇을 필요로 하는지 드러나지 않는다.** 생성자에는 그 클래스 전체의 협력자가 모여 있어, 특정 동작이 실제로 무엇을 쓰는지는 본문을 읽어야 안다.

포트가 응용 계층에 있는 것 자체는 문제가 아니다. 요구하는 쪽이 인터페이스를 소유하는 것이 맞고, 구현이 `adapter/out`에서 그것을 구현하므로 의존 방향도 안쪽을 향한다. 문제는 배치가 아니라 **한 패키지 안이 평평하다는 것**이다.

들어온 호출을 받는 쪽(`adapter/in`)에는 인터페이스가 없다는 비대칭도 있다. 컨트롤러가 구현 클래스를 직접 참조한다. 입력 쪽은 의존 방향이 이미 안쪽을 향해 뒤집을 것이 없으므로 인터페이스가 필수는 아니지만, 유스케이스 목록을 드러내는 수단은 되지 못한다.

## 목표

응용 계층을 열었을 때 무엇이 유스케이스이고 무엇이 바깥에 요구하는 계약인지가 패키지 구조로 드러난다. 각 유스케이스가 필요로 하는 것이 타입으로 명시되어, 호출하는 쪽이 그 유스케이스만 알고도 쓸 수 있다.

**payment-service에 먼저 적용해 검증한다.** 나머지 서비스로 옮기는 것은 [BL-0042](bl-0042-apply-application-structure-to-all-services.md)가 담는다. 그때까지 저장소에 두 가지 관행이 공존한다.
