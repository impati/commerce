# 인프라를 컨테이너로 세우고 실 DB로 옮긴다

- **ID:** BL-0053
- **기록일:** 2026-08-29

## 배경

저장소를 가진 여덟 서비스가 전부 H2 파일 DB를 쓴다. H2는 자바 라이브러리라 테스트 프로세스 안에서 뜨고, 그래서 지금 하네스는 외부 프로세스 없이 돈다. 편하지만 대가가 있다 — **운영에서 쓸 DB의 동작이 한 번도 검증되지 않는다.**

가장 위험한 지점이 점유다. [ADR-0011](../adr/0011-deliver-verification-mail-once.md)이 `for update skip locked` 위에 배타성을 세웠는데, 이 구문의 잠금 범위와 격리 수준별 동작은 DB마다 다르다. H2에서 통과하는 것이 운영 DB에서 같게 돈다는 근거가 없다.

`docker-compose.yml`은 서비스 열 개만 담고 인프라 컨테이너가 하나도 없다. 그리고 **한 번도 실행해보지 않았다** — 문서에 있는 실행 경로가 동작하는지 아무도 모르는 상태다. 이 항목은 BL-0014를 대체한다.

이 저장소의 이력이 같은 실수를 반복해서 보여줬다. `./gradlew test`가 두 달간 실행조차 되지 않던 상태에서 하네스를 세운 것이 출발점이었고, 검증되지 않는 경로는 반드시 샌다. 실 DB를 도입하면서 테스트를 H2에 남겨두면 검증되지 않은 경로를 하나 더 만드는 것이다.

## 목표

여덟 서비스가 운영에서 쓸 DB 위에서 돌고, 그 경로를 하네스가 검증한다. compose로 띄우는 경로가 실제로 동작한다.

정해야 할 것과 이미 정해진 것이 섞여 있다.

**정해졌다.** DB는 MySQL 8. 하네스는 Testcontainers로 실 인프라를 띄우며 게이트는 `make verify` 하나로 유지한다 — CI가 없으므로 게이트를 둘로 나누면 강제되지 않는 쪽이 방치된다. 그 결과 커밋마다 도커가 필요해지고, `pre-commit` 훅과 CLAUDE.md의 검증 절을 함께 고쳐야 한다.

**MySQL로 가면서 고쳐야 하는 것 셋.**

- **묶음 점유 SQL.** MySQL은 `update t ... where id in (select ... from t ...)`를 거절한다(ER 1093). 파생 테이블로 감싸면 materialize되어 `for update skip locked`의 잠금이 의미를 잃는다. 한 트랜잭션 안의 두 문장(`select ... for update skip locked` → `update ... where id in (:ids)`)으로 바꿔야 하며, 락이 커밋까지 유지되므로 원자성은 그대로다. notification-service의 기존 SQL도 대상이다.
- **격리 수준.** MySQL 기본값 REPEATABLE READ에서 `for update` 범위 읽기는 갭 락까지 잡는다. 삽입이 계속 일어나는 큐 테이블에서 점유와 삽입이 교착할 수 있다. READ COMMITTED로 낮출지 정해야 한다.
- **타입 둘.** 마이그레이션이 쓰는 `timestamp with time zone`은 MySQL에 대응 타입이 없다(UTC 저장 규약 + `DATETIME(6)`을 정해야 한다). `generated by default as identity`는 `AUTO_INCREMENT`가 되며, 그 컬럼은 인덱스를 요구하는데 `seq`가 PK가 아니라 인덱스를 명시해야 한다.

레디스는 **자리만 두고 만들지 않는다.** 쓰는 코드가 없는 컨테이너는 검증되지 않은 설정일 뿐이다.
