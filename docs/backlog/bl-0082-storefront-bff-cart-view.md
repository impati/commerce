# Storefront BFF를 도입하고 장바구니 화면 데이터를 조합한다

- **ID:** BL-0082
- **기록일:** 2026-09-16

## 배경

현재 storefront는 여러 도메인의 API를 직접 호출해 화면을 구성하고, 장바구니 합계를 프론트엔드에서 SKU 가격과 수량으로 계산한다. 상품 정보를 찾지 못하면 해당 줄의 금액이 0원으로 계산될 수 있으며, 화면의 금액과 주문 접수 시 서버가 계산한 금액이 달라질 수 있다.

장바구니와 주문서 등 지면이 고도화되면 상품, 재고, 배송지와 구매 금액을 조합할 요구가 늘어난다. 화면을 위한 조합 책임을 게이트웨이나 도메인 서버에 계속 추가하면 화면의 변경과 도메인 규칙의 변경이 섞인다. 화면 조합의 오너십과 업무 규칙의 오너십을 명시적으로 구분할 필요가 있다.

## 목표

Storefront BFF가 화면 데이터를 조합하는 책임을 명시적으로 맡고, 각 도메인 서버는 데이터와 업무 규칙의 소유권을 유지한다. 첫 적용 대상인 장바구니 화면은 BFF를 통해 상품 정보, 장바구니 상태, 재고와 주문 서버가 계산한 견적을 받아 표시하며, 프론트엔드나 BFF가 구매 금액 계산 규칙을 중복 구현하지 않는다.
