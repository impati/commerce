# Gateway와 BFF의 I/O 실행 모델 검토

- **ID:** BL-0083
- **기록일:** 2026-09-17

## 배경

Gateway와 Storefront BFF는 하위 서버를 호출하고 응답을 기다리는 I/O 작업이 많다. 지면의 요구사항과 동시 요청이 늘어날수록 이러한 대기가 요청 처리 스레드와 자원 사용에 어떤 영향을 주는지 확인할 필요가 있다.

현재 두 서버는 Spring MVC와 블로킹 RestClient를 사용한다. BFF는 장바구니의 하위 조회를 병렬 실행하는 데 이미 가상 스레드를 사용하지만, 들어오는 HTTP 요청 처리까지 가상 스레드를 적용한 구성은 아니다. 현재 구조에서 병목이 발생하는지는 아직 측정하지 않았으므로, 가상 스레드 적용 범위를 넓히는 방안과 WebFlux를 사용하는 방안의 적합성을 검토해야 한다.

## 목표

Gateway와 BFF 각각의 요청 처리부터 하위 HTTP 호출 대기까지 실행 모델을 검토하고, 현재 방식 유지, 가상 스레드 적용 확대, WebFlux 도입 중 적합한 방향을 판단한다. 동시 부하에 따른 처리량·응답 지연·자원 사용과 함께 기존 코드와의 호환성, 타임아웃·취소 처리, 개발 및 운영 복잡도를 비교해 도입 필요성과 적용 범위를 정한다.
