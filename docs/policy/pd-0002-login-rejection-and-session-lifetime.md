# PD-0002: 로그인 거절과 세션 수명

- **날짜:** 2026-08-17
- **대체:** 해당 없음
- **대체됨:** [PD-0014](pd-0014-login-rejection-and-session-lifetime.md)

> 이 문서는 이미 구현되어 있던 규칙을 코드에서 읽어 옮긴 것이다. 규칙은 코드에서 확인한 사실이고, 근거는 주석이나 기존 문서에 기록이 남아 있는 것만 적었다. 기록이 없으면 `근거 미기록`으로 둔다.

## 배경과 문제

이 정책은 **로그인을 언제 거절하고 그때 무엇을 알려주는가**, 그리고 **한 번 확인한 신원을 얼마나 오래 믿는가**에 답한다. [PD-0001](pd-0001-signup-and-email-verification.md)이 계정이 생기는 시점까지를 다루고, 이 문서는 그 계정으로 요청을 보내는 구간을 다룬다.

로그인 거절 응답은 공격자에게 가장 값싼 정보원이다. 거절 이유를 구분해 알려주면 어떤 이메일이 가입돼 있는지 목록을 만들 수 있고, 그 목록은 표적 피싱과 비밀번호 대입의 입력이 된다. 반대로 아무것도 알려주지 않으면 정당한 사용자가 자기 상태를 알 수 없다.

세션 수명은 반대 방향의 교환이다. 길면 재로그인 부담이 줄고, 짧으면 탈취된 토큰의 유효 기간이 줄어든다.

## 목표

**로그인 경로는 계정의 존재 여부를 알려주지 않는다.** 그리고 신원이 더 이상 유효하지 않다고 판단되는 순간, 만료를 기다리지 않고 그 신원을 끊을 수 있어야 한다. 세션 토큰은 그것을 가진 사람이 계정으로 행세할 수 있으므로 비밀번호와 같은 급으로 다룬다.

## 정책

- **PD-0002-R1:** 등록되지 않은 이메일과 비밀번호 불일치는 구분하지 않고 같은 응답으로 거절한다. 근거: 구분해서 알려주면 어떤 이메일이 가입돼 있는지 열거할 수 있다.
- **PD-0002-R2:** 소유 확인을 마치지 않은 계정의 로그인은 확인이 필요하다는 사실을 알리며 거절한다. R1과 달리 다른 응답을 준다. 근거 미기록.
- **PD-0002-R3:** 로그인에 성공할 때마다 새 세션이 발급되며 기존 세션은 그대로 유지된다. 한 계정이 동시에 가질 수 있는 세션 수에 제한을 두지 않는다. 근거 미기록.
- **PD-0002-R4:** 세션은 발급 후 14일이 지나면 만료된다. 사용해도 만료 시각은 연장되지 않는다. 근거 미기록.
- **PD-0002-R5:** 로그아웃은 세션을 즉시 폐기한다. 폐기된 세션은 만료 시각 전이라도 사용할 수 없다. 근거: 로그아웃은 지연 없이 반영되어야 하며, 그 즉시성을 얻기 위해 서버가 세션 상태를 갖는 방식을 택했다.
- **PD-0002-R6:** 이미 폐기되었거나 존재하지 않는 세션에 대한 로그아웃 요청도 성공으로 처리한다. 근거 미기록.
- **PD-0002-R7:** 유효하지 않은 세션 토큰은 이유를 구분하지 않고 같은 응답으로 거절한다. 만료, 폐기, 존재하지 않음, 형식 오류를 모두 같게 취급한다. 근거 미기록.

## 거절하는 시나리오

- 가입하지 않은 이메일로 로그인하면 거절된다. 응답만 보고는 그 이메일이 없어서인지 비밀번호가 틀려서인지 알 수 없다 (R1).
- 소유 확인을 마치지 않은 사용자는 비밀번호가 맞아도 로그인할 수 없다 (R2).
- 로그아웃한 뒤 이전 토큰으로 보낸 요청은 만료 시각이 남아 있어도 거절된다 (R5).
- 발급 후 14일이 지난 토큰은 계속 사용 중이었더라도 거절된다 (R4).
- 형식이 맞지 않는 토큰과 폐기된 토큰은 같은 응답으로 거절된다. 어느 쪽인지 알 수 없다 (R7).

## 허용하는 시나리오

- **미인증 계정의 존재는 로그인 응답으로 드러난다.** R2가 R1과 다른 응답을 주므로, 확인이 필요하다는 응답이 오면 그 이메일이 가입돼 있다는 뜻이 된다. R1이 막으려는 열거가 이 경로로는 성립한다.
- 여러 기기에서 각각 로그인하면 세션이 여러 개 동시에 유효하다. 한쪽에서 로그아웃해도 나머지는 살아 있다 (R3, R5).
- 14일 내내 사용하던 사용자도 만료 시각이 되면 다시 로그인해야 한다 (R4).
- 이미 로그아웃한 상태에서 로그아웃을 다시 요청해도 오류가 아니다 (R6).

## 정책이 정하지 않는 것

- 세션 토큰을 어떤 형식으로 만들고 어떻게 보관하는가. 별도 기술 결정의 대상이다.
- 클라이언트가 토큰을 어디에 저장하는가.
- 로그인 시도 횟수 제한과 잠금.
- 비밀번호를 바꿨을 때 기존 세션을 어떻게 할 것인가. 비밀번호 변경 기능이 아직 없다.
- 계정이 정지되었을 때 기존 세션을 어떻게 할 것인가.
- 세션 확인 결과를 캐시할 것인가와 그 유효 기간.

## 고려한 대안

**R4의 대안 — 사용할 때마다 만료를 연장한다.** 기록 없음. 현재는 발급 시각 기준 고정 만료다.

**R3의 대안 — 동시 세션 수를 제한하거나 새 로그인이 기존 세션을 폐기한다.** 기록 없음.

나머지 규칙도 기록 없음. 이 문서는 이미 구현된 규칙을 옮긴 것이며 당시 검토한 대안이 남아 있지 않다.

## 재검토 조건

아래 조건은 이 문서를 작성하면서 정한 것이며, 원래 결정 시점의 판단이 아니다.

- 계정 열거를 이용한 공격이 실제로 관측될 때 (R1, R2).
- 비밀번호 변경이나 계정 정지 기능을 도입할 때. 기존 세션을 어떻게 할지가 이 정책의 빈칸이다 (R3, R5).
- 세션 탈취 사고가 관측되거나, 14일이 길다는 판단 근거가 생길 때 (R4).
- 재로그인 빈도가 사용자 이탈 요인으로 보고될 때 (R4).

## 미결

없음. 이 문서는 결정을 새로 하지 않고 현행 규칙을 기록한 것이다. R2가 R1의 목표를 무너뜨리는 문제는 미결이 아니라 별도 작업 항목으로 분리했으며, 그 작업이 규칙을 바꾸면 이 문서를 고치지 않고 새 정책 문서로 대체한다.
