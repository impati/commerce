# PD-0010: 배송 진행

- **날짜:** 2026-08-17
- **대체:** 해당 없음
- **대체됨:** 해당 없음

> 이 문서는 이미 구현되어 있던 규칙을 코드에서 읽어 옮긴 것이다. 근거는 기록이 남아 있는 것만 적었고, 없으면 `근거 미기록`으로 둔다.

## 배경과 문제

이 정책은 **배송이 어떤 상태를 거치고 각 전이가 언제 가능한가**에 답한다.

배송은 주문과 별개의 생애주기를 갖는다. 물건이 실제로 움직이는 것을 기록하므로 시스템이 그 순서를 강제할 수 없는 구간이 있고, 그래서 어떤 건너뛰기를 허용할지가 판단의 대상이 된다.

[PD-0003](pd-0003-order-lifecycle-and-cancellation.md)이 정하는 주문 상태와 여기서 정하는 배송 상태는 이름이 겹치지만 서로 다른 것이다. 둘의 관계를 정해두지 않으면 어느 쪽이 진실인지 물었을 때 답할 수 없다.

## 목표

**배송 상태는 물건의 실제 위치를 뒤늦게라도 정확히 반영한다.** 실제로 일어난 일을 기록하지 못해 상태가 막히는 일이 없어야 하고, 동시에 되돌아가는 전이는 허용하지 않는다.

## 정책

- **PD-0010-R1:** 배송은 준비 상태로 만들어지며, 운송장 번호는 이때 함께 발급된다. 근거 미기록.
- **PD-0010-R2:** 출고는 준비 상태에서만 할 수 있다. 근거 미기록.
- **PD-0010-R3:** 배송 완료는 준비 또는 배송 중 상태에서 할 수 있다. 출고를 기록하지 않았어도 완료할 수 있다. 근거 미기록.
- **PD-0010-R4:** 배송지는 배송 생성 시점의 사본이다. 회원의 주소록이 바뀌어도 배송에 남은 값은 변하지 않는다. 근거 미기록.
- **PD-0010-R5:** 배송에는 취소와 반품 상태가 없다. 한 번 만들어진 배송은 완료를 향해서만 움직인다. 근거 미기록.
- **PD-0010-R6:** 배송 상태와 주문 상태는 각각 따로 전이된다. 한쪽을 바꾸는 것이 다른 쪽을 자동으로 바꾸지 않는다. 근거 미기록.

## 거절하는 시나리오

- 이미 출고된 배송을 다시 출고할 수 없다 (R2).
- 완료된 배송을 다시 완료하거나 출고로 되돌릴 수 없다 (R2, R3).

## 허용하는 시나리오

- 출고를 기록하지 않고 준비 상태에서 바로 완료할 수 있다. 실제 배송이 이미 끝난 뒤에 기록하는 경우를 위한 것이다 (R3).
- **배송은 완료인데 주문은 이행 중으로 남을 수 있다.** 두 상태는 따로 움직이므로 어느 한쪽만 기록하면 서로 어긋난 채로 남는다 (R6).
- 주문이 취소되어도 배송은 그대로 진행된다. 배송을 멈추는 상태가 없다 (R5).
- 배송지가 잘못되어도 고칠 방법이 없다. 배송지는 생성 시점에 고정된다 (R4).

## 정책이 정하지 않는 것

- 운송장 번호를 어떻게 만드는가.
- 실제 배송사와의 연동과 상태 동기화.
- 출고와 완료를 누가 언제 기록하는가.
- 배송 실패와 반송의 처리.
- 하나의 주문을 여러 번에 나눠 보낼 수 있는가.

## 고려한 대안

기록 없음. 이 문서는 이미 구현된 규칙을 옮긴 것이며 당시 검토한 대안이 남아 있지 않다.

## 재검토 조건

아래 조건은 이 문서를 작성하면서 정한 것이다.

- 실제 배송사를 연동해 상태가 외부에서 들어오기 시작할 때 (R3, R6).
- 반품이나 교환을 도입할 때 (R5).
- 배송과 주문의 상태가 어긋난 사례가 관측될 때 (R6).
- 한 주문을 나눠 보내야 할 때.
