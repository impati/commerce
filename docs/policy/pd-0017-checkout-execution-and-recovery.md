# PD-0017: 체크아웃 실행과 복구

- **날짜:** 2026-09-11

## 배경과 문제

체크아웃은 주문, 장바구니, 재고, 결제, 배송을 하나의 DB 트랜잭션으로 묶을 수 없다. 외부 처리가 성공한 뒤 주문 저장이나 응답이 실패하면 호출자는 결과를 모르고, 프로세스가 종료되면 메모리에 있던 진행 상황과 보상 절차도 사라진다.

## 목표

체크아웃은 몇 번 호출되거나 어느 단계에서 중단되어도 주문 하나와 확정된 구매 결과 하나로 끝난다. 매입 전 실패는 보상하고, 매입이 확인된 주문은 취소하지 않고 남은 단계를 완료한다.

## 정책

- **PD-0017-R1:** 인증된 회원의 체크아웃 접수는 회원 범위의 멱등 키로 식별한다. 같은 키와 같은 요청은 기존 주문과 결과를 반환하고, 같은 키에 다른 요청이 오면 거절한다. 키 매핑은 성공·실패 뒤에도 보존한다.
- **PD-0017-R2:** 주문 식별자는 서버가 발급한다. 멱등 키는 체크아웃 접수와 최초 응답 복구에만 쓰며, 주문 조회와 서비스 간 업무 식별자는 주문 식별자를 사용한다.
- **PD-0017-R3:** 구매 내용, 가격과 배송지는 최초 접수 시점의 사본으로 고정한다. 이후 장바구니나 주소록이 바뀌어도 이미 접수한 주문은 바뀌지 않는다.
- **PD-0017-R4:** 체크아웃은 장바구니 구매분 분리, 재고 예약, 결제 승인, 배송 생성, 결제 매입, 주문 확정, 재고 확정 순서로 진행한다. 각 단계는 저장된 진행 상태에서 다시 시작할 수 있어야 한다.
- **PD-0017-R5:** 재고 예약, 결제 승인과 배송 생성은 주문 식별자에 대해 멱등하다. 같은 주문과 같은 내용은 기존 결과를 반환하고, 다른 내용은 거절한다. 매입·취소·환불·예약 확정·예약 해제·배송 취소도 반복 호출 결과가 같다.
- **PD-0017-R6:** 외부 호출 결과를 알 수 없으면 즉시 한 번 같은 요청을 반복한다. 여전히 알 수 없으면 매입 전에는 실패 보상으로 전환하고, 매입 여부를 알 수 없는 경우에는 결제 상태를 확인해 승인 취소 또는 환불한다.
- **PD-0017-R7:** 매입 전에 체크아웃이 실패하면 배송 취소, 승인 취소, 예약 해제와 주문 실패 처리를 끝까지 수행한다. 일부 보상이 실패하거나 프로세스가 종료되어도 저장된 진행 상태에서 다시 수행한다.
- **PD-0017-R8:** 매입 성공이 확인되면 구매는 성공이다. 이후 주문 저장, 재고 확정 또는 후속 처리가 실패해도 주문을 실패나 취소로 바꾸지 않고 자동 복구와 운영 절차로 완료한다.
- **PD-0017-R9:** 고객에게 보이는 구매 결과는 `PROCESSING`, `SUCCEEDED`, `FAILED`로 구분한다. 결제 정리가 남은 실패는 정리 중임을 함께 보여주며, 내부 단계와 오류 내용은 노출하지 않는다.
- **PD-0017-R10:** 정상 요청은 API가 실행한다. API에서 종단 결과를 확정하지 못하면 `PROCESSING`과 주문 식별자를 반환하고, 워커가 중단된 진행 또는 보상을 이어간다. 같은 주문은 같은 시각에 한 실행자만 상태를 확정한다.
- **PD-0017-R11:** 자동 복구가 안전하게 진행될 수 없는 데이터 불일치나 분류되지 않은 오류는 운영 확인 대상으로 남긴다. 운영 신호를 남기는 방식은 교체할 수 있어야 한다.
- **PD-0017-R12:** 빈 장바구니, 변경된 장바구니, 재고 부족, 결제 거절은 각각 안정된 실패 코드로 구분한다. 외부 시스템 오류와 상세 메시지는 고객에게 노출하지 않는다.

## 거절하는 시나리오

- 멱등 키가 없거나 같은 키에 다른 요청 내용을 보내면 접수하지 않는다 (R1).
- 구매 스냅샷을 만든 뒤 장바구니가 바뀌었으면 해당 요청을 실패로 끝낸다 (R3, R12).
- 빈 장바구니, 재고 부족, 결제 거절은 실패 결과로 끝난다 (R12).

## 허용하는 시나리오

- 최초 응답을 잃은 클라이언트가 같은 요청을 반복해 기존 주문 식별자와 결과를 얻을 수 있다 (R1, R2).
- 결제가 매입된 뒤 주문 확정 저장이 중단되어 한동안 `PROCESSING`으로 보일 수 있다. 복구가 끝나면 `SUCCEEDED`가 된다 (R8~R10).
- 실패한 주문의 승인 취소나 환불이 끝나기 전까지 결제 정리 중으로 보일 수 있다 (R7, R9).

## 정책이 정하지 않는 것

- 임차 시간, 재시도 간격, 배치 크기와 워커 실행 주기.
- 진행 상태의 테이블과 클래스 구조.
- 운영 신호의 전달 수단과 알림 규칙.
- 실패한 구매를 장바구니에 다시 담는 기능.
- 범용 워크플로 엔진과 서비스 간 분산 트랜잭션.

## 재검토 조건

- 부분 결제, 부분 배송 또는 부분 취소를 지원할 때.
- 결제 대행사의 멱등·조회 규격이 주문 식별자를 사용할 수 없을 때.
- 자동 복구 대상이 체크아웃 밖의 여러 업무로 늘어날 때.
- 운영 확인 대상이 반복적으로 발생해 별도 처리 도구가 필요할 때.
