# PD-0020: 주문 내역 노출과 진행 이력

- **날짜:** 2026-09-16
- **대체:** PD-0019
- **대체됨:** 해당 없음

## 배경과 문제

체크아웃은 주문을 먼저 접수한 뒤 재고, 결제와 배송을 차례로 처리하며, 중단된 단계는 별도 실행자가 이어간다. 이전 정책은 성공이나 실패로 종결된 주문만 주문 내역에 표시했지만, 접수된 주문이 처리 중이라는 이유로 내역에 없으면 고객은 요청이 유실되었다고 오해할 수 있다.

주문을 즉시 보여주면서도 내부 실행 단계와 복구 절차를 그대로 노출하지 않도록, 주문의 노출 시점과 고객에게 보여줄 상태·정보의 경계를 정해야 한다.

## 목표

회원은 접수된 자신의 주문을 주문 내역에서 즉시 찾고, 처리 중부터 성공이나 실패까지의 고객 관점 상태를 끊김 없이 확인할 수 있다. 내부 복구 정보와 다른 회원의 주문 정보는 드러나지 않는다.

## 정책

- **PD-0020-R1:** 체크아웃 요청이 접수되어 주문이 생성되면 처리 결과가 확정되지 않았더라도 회원의 주문 내역에 즉시 나타난다. 근거: 고객이 제출한 주문의 존재와 처리 여부를 같은 주문 내역에서 계속 확인할 수 있어야 한다.
- **PD-0020-R2:** 정상 처리가 진행 중이거나 실패를 되돌리는 절차가 진행 중인 주문은 고객에게 하나의 `주문 처리 중` 상태로 나타난다. 내부 실행 단계와 복구 여부는 구분해 보여주지 않는다. 근거: 고객에게 필요한 것은 처리가 끝나지 않았다는 사실이며 내부 절차의 구분은 후속 행동에 도움이 되지 않는다.
- **PD-0020-R3:** 자동 복구로 종결할 수 없어 운영 확인이 필요한 주문도 내역에서 숨기지 않고 고객에게 `확인 중` 상태로 나타난다. 근거: 운영 대응 여부와 별개로 이미 접수된 주문이 사라져서는 안 된다.
- **PD-0020-R4:** 체크아웃이 성공하면 주문은 결제·배송을 포함한 현재 주문 진행 상태를 나타내고, 실패를 되돌리는 절차까지 끝나면 `구매 실패` 상태를 나타낸다. 상태가 바뀌는 동안 같은 주문이 내역에서 사라지지 않는다. 근거: 고객은 하나의 주문에서 접수 이후의 결과와 후속 진행을 이어서 확인할 수 있어야 한다.
- **PD-0020-R5:** 주문 목록의 각 항목에는 주문 식별자와 주문 시각, 대표 상품의 이름과 선택 항목, 나머지 상품 종류 수, 총수량, 총금액과 통화, 고객 관점의 처리 결과 및 현재 주문 상태가 나타난다. 근거: 고객이 상세 화면을 열기 전에 주문을 구별하고 현재 상황을 판단할 수 있어야 한다.
- **PD-0020-R6:** 주문 목록은 새로 접수된 주문부터 나타나며, 다음 항목을 불러오더라도 같은 주문이 중복되거나 누락되지 않는다. 근거: 주문이 계속 추가되는 동안에도 과거 내역을 안정적으로 탐색할 수 있어야 한다.
- **PD-0020-R7:** 주문 상세에는 주문 식별자와 주문 시각, 모든 주문 상품의 이름·선택 항목·수량·단가·합계, 주문 총금액과 통화, 주문 당시 수령인·연락처·주소, 고객 관점의 현재 상태, 운송장 번호가 존재하면 그 번호, 그리고 고객에게 의미 있는 진행 이력이 나타난다. 근거: 고객이 구매 내용과 배송 대상, 현재 진행 상황을 한 화면에서 확인할 수 있어야 한다.
- **PD-0020-R8:** 진행 이력에는 고객에게 의미 있는 주문 사실과 각 사실이 발생한 시각이 발생 순서대로 나타난다. 내부 실행 단계, 재시도 횟수, 발행 상태, 내부 식별자와 내부 오류 내용은 나타나지 않는다. 근거: 고객은 구매 진행을 이해할 정보가 필요하지만 내부 복구와 운영 정보는 고객의 판단 대상이 아니다.
- **PD-0020-R9:** 회원은 자신이 소유한 주문의 목록, 상세와 진행 이력만 조회할 수 있다. 다른 회원이 소유한 주문은 존재하지 않는 주문과 같은 결과로 거절한다. 근거: 주문 식별자를 아는 것만으로 주문의 존재나 상품, 금액, 배송지와 결제 상태를 알아낼 수 없어야 한다.

## 거절하는 시나리오

- 처리 중인 주문을 내부 단계별 상태나 실패 복구 중이라는 이유로 주문 내역에서 숨기지 않는다 (R1, R2, R4).
- 운영 확인이 필요하다는 이유로 이미 접수된 주문을 주문 내역에서 숨기지 않는다 (R3).
- 고객에게 내부 실행 단계, 재시도나 발행 상태, 내부 식별자와 내부 오류 내용을 제공하지 않는다 (R2, R8).
- 다른 회원의 주문 식별자로 상세나 진행 이력을 조회하면 존재하지 않는 주문과 같은 결과를 받는다 (R9).

## 허용하는 시나리오

- 체크아웃 요청 직후 아직 재고나 결제 처리가 끝나지 않은 주문도 주문 내역에서 `주문 처리 중`으로 확인할 수 있다 (R1, R2).
- 실패를 되돌리는 중인 주문은 내역에 계속 남고, 절차가 끝난 뒤 `구매 실패`로 바뀐다 (R2, R4).
- 운영 확인이 필요한 주문은 내역에 계속 남고 `확인 중`으로 안내된다 (R3).
- 체크아웃에 성공한 뒤 배송 준비 또는 배송 중인 주문은 같은 상세에서 현재 주문 상태와 새 진행 이력을 이어서 보여준다 (R4, R7, R8).
- 상품이 여러 개인 주문은 목록에서 대표 상품과 나머지 상품의 존재를 요약하고, 상세에서 모든 상품을 확인할 수 있다 (R5, R7).

## 정책이 정하지 않는 것

- 주문 목록의 페이지 크기, 페이지를 이어서 조회하는 값의 표현과 화면 배치.
- 대표 상품을 선택하는 구현 방식과 상태별 문구의 시각적 표현.
- 진행 사실과 발생 시각을 저장하고 조회하는 구현 방식.
- 운영 확인 대상의 알림, 재처리와 관리 방법.
- 주문과 진행 이력의 보관 기간.

## 고려한 대안

**성공이나 실패로 종결된 주문만 내역에 표시한다 — 채택하지 않음.** 접수되어 정상 처리 또는 복구 중인 주문이 내역에 없어 고객이 요청 유실로 오해할 수 있다. 이 대안은 PD-0019에서 채택했으나, 주문의 존재를 숨기는 비용이 내부 과정을 감추는 이점보다 크다고 판단해 대체한다.

**운영 확인이 필요한 주문은 내역에서 숨긴다 — 채택하지 않음.** 고객이 이미 확인한 주문이 처리 문제로 사라질 수 있다. 운영 알림과 재처리는 별도 절차로 다루고 주문의 존재는 유지한다.

**체크아웃의 내부 단계를 그대로 표시한다 — 채택하지 않음.** 내부 단계와 복구 절차는 고객이 선택하거나 해결할 수 있는 상태가 아니며, 구현 변화에 따라 고객 경험이 불필요하게 달라진다.

**배송 완료와 취소처럼 주문 생애주기의 끝 상태만 표시한다 — 채택하지 않음.** 결제가 확정되어 배송을 기다리는 정상 주문뿐 아니라 방금 접수된 주문도 내역에서 찾을 수 없다.

## 재검토 조건

- 처리 중인 체크아웃에서 고객의 선택이나 추가 행동이 필요해질 때.
- `주문 처리 중` 또는 `확인 중` 상태가 장시간 유지되어 별도의 고객 안내나 문의 경로가 필요해질 때.
- 운영 확인 대상의 원인 일부를 고객에게 구분해 안내하기로 할 때.
- 비회원 주문 조회나 주문 데이터 보관 기간을 도입할 때.
