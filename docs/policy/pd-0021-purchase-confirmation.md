# PD-0021: 확인한 구매 내용과 금액으로 주문한다

- **날짜:** 2026-09-16
- **대체:** 해당 없음

## 배경과 문제

장바구니 화면을 확인한 뒤 다른 탭에서 상품이나 수량을 바꾸거나 판매 가격이 달라질 수 있다. 최신 상태만으로 주문하면 사용자가 확인하지 않은 상품이나 금액으로 구매할 수 있다. 조회 실패를 데모 상태나 0원으로 대체하면 실제 구매 상태를 오해하게 된다.

## 목표

사용자가 확인한 구매 내용과 금액이 접수 시점의 상태와 일치할 때 주문한다. 실패나 결과 미확인을 성공으로 표시하지 않는다.

## 정책

- **PD-0021-R1:** 견적은 서버가 계산하며 가격이나 재고를 예약하지 않는다.
- **PD-0021-R2:** 견적 확인 이후 금액이 오르거나 내려가면 주문을 접수하지 않고 새 견적을 확인받는다. 근거: 확인하지 않은 금액을 청구하지 않기 위해서다.
- **PD-0021-R3:** 확인한 장바구니의 버전과 현재 버전이 다르면 새 구매 내용과 견적을 확인받는다. 접수된 구매분은 이후 변경과 분리된다.
- **PD-0021-R4:** 조회 실패는 확인된 정보와 구분해서 표시한다. 견적이나 재고를 확인하지 못하면 결제를 제한하고, 금액을 0원이나 데모 데이터로 대체하지 않는다.
- **PD-0021-R5:** 장바구니 변경 성공과 후속 조회 실패를 구분한다. 저장 여부를 모르면 성공이나 실패를 단정하지 않으며 변경 요청을 자동 반복하지 않는다.
- **PD-0021-R6:** 같은 주문 요청의 반복은 최초 구매 결과를 회수하며, 이후 가격이나 장바구니 변경이 최초 결과를 바꾸지 않는다.

## 거절하는 시나리오

- 다른 탭에서 구매 수량을 바꾼 뒤 이전 화면에서 결제한다.
- 확인한 견적과 접수 시점의 가격이 달라진다.
- 견적이나 재고를 확인할 수 없는 상태에서 새 결제를 시도한다.

## 허용하는 시나리오

- 일부 조회가 실패해도 확인된 장바구니 정보는 유지한다.
- 상품 담기는 성공했지만 금액 조회가 실패하면 담기 성공을 알리고 조회만 다시 시도한다.
- 주문 접수 뒤 가격이 바뀌어도 같은 요청으로 접수 결과를 회수한다.

## 정책이 정하지 않는 것

견적 식별과 검증 방법, 병렬 조회 방법, 쿠폰 및 배송비 부과 규칙, 장바구니 줄 변경과 삭제 API.

## 고려한 대안

최신 금액으로 바로 접수하는 방법은 확인하지 않은 금액을 청구할 수 있어 제외했다. 일부 조회 실패에서 전체 화면을 실패시키는 방법은 확인된 정보까지 숨기므로 제외했다.

## 관련 정책

PD-0017의 접수 시점 구매 사본과 멱등 접수에 확인 조건을 추가한다. PD-0018의 장바구니 버전 검증과 구매분 분리 원칙을 유지한다.
