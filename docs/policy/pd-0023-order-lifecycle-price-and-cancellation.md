# PD-0023: 주문 생애주기, 금액 구성과 취소

- **날짜:** 2026-09-19
- **대체:** PD-0003
- **대체됨:** 해당 없음

## 배경과 문제

주문은 돈과 물건이 오가는 기록이므로 상태가 임의로 뒤바뀌거나 이미 합의한 구매 내용이 나중의 변경에 따라 달라지면 안 된다. 기존 정책은 주문 총액을 상품 라인 금액의 합으로만 정의해 배송비와 최종 청구 금액의 관계를 설명하지 못했다.

고객이 결제 전에 상품 금액과 배송비를 구분해 확인하고, 주문 뒤에도 같은 구성을 확인할 수 있도록 배송비 부과 기준과 주문 금액의 구성, 견적 변경 시 재확인 기준을 함께 정한다.

## 목표

주문은 정해진 생애주기만 따르고, 고객은 원화 상품 금액과 배송비로 구성된 최종 결제 금액을 확인한 뒤 주문한다. 접수된 주문의 금액과 배송지는 이후 상품 가격, 배송비 정책과 주소록이 바뀌어도 변하지 않는다.

## 정책

- **PD-0023-R1:** 주문은 생성 시점에 결제 전 상태이며, 결제가 확정되면 결제됨으로 넘어간다. 결제 전 상태가 아닌 주문은 결제할 수 없다. 근거 미기록.
- **PD-0023-R2:** 배송은 결제된 주문에만 붙일 수 있다. 배송이 붙으면 주문은 이행 중 상태가 된다. 근거 미기록.
- **PD-0023-R3:** 배송 완료 처리는 결제됨 또는 이행 중 상태에서만 가능하다. 배송이 붙지 않은 결제된 주문도 완료 처리할 수 있다. 근거 미기록.
- **PD-0023-R4:** 배송이 완료된 주문은 취소할 수 없다. 그 밖의 모든 상태에서는 취소할 수 있다. 근거 미기록.
- **PD-0023-R5:** 상품 금액은 주문 시점의 각 상품 단가와 수량을 곱한 라인 금액의 합이며 모든 금액은 원화여야 한다. 비원화 상품이 포함된 견적과 주문은 거절한다. 근거: 환율이나 통화별 배송비를 정하지 않은 상태에서 서로 다른 통화의 수치를 청구 금액으로 합치지 않기 위해서다.
- **PD-0023-R6:** 한 주문의 상품 금액이 50,000원 이상이면 배송비는 0원이고, 50,000원 미만이면 배송비는 3,000원이다. 무료배송 기준에는 배송비 자체를 포함하지 않는다. 근거: 첫 배송비 정책은 주문 단위의 예측 가능한 단일 기준으로 시작한다.
- **PD-0023-R7:** 최종 결제 금액은 상품 금액과 배송비의 합이며, 견적과 접수된 주문은 같은 세 금액을 사용한다. 근거: 고객이 확인한 구성과 실제 청구 금액이 달라지지 않아야 한다.
- **PD-0023-R8:** 장바구니, 결제 결과, 주문 목록과 주문 상세에는 상품 금액, 배송비와 최종 결제 금액이 구분되어 나타난다. 근거: 고객이 결제 전후 어느 주문 화면에서도 배송비가 포함된 이유를 확인할 수 있어야 한다.
- **PD-0023-R9:** 견적 확인 뒤 상품 내용이나 금액 정책의 적용 결과가 달라져 세 금액 중 하나라도 바뀌면 주문을 접수하지 않고 새 견적 확인을 요구한다. 정책이 바뀌어도 해당 주문의 금액 구성이 같다면 새 확인을 요구하지 않는다. 근거: 고객이 확인하지 않은 금액은 청구하지 않되 결과가 같은 내부 정책 변경으로 구매를 불필요하게 막지 않기 위해서다.
- **PD-0023-R10:** 접수된 주문은 상품 금액, 배송비와 최종 결제 금액을 주문 시점의 값으로 유지한다. 이후 상품 가격이나 배송비 정책이 바뀌어도 기존 주문과 같은 주문 요청의 결과는 바뀌지 않는다. 근거: 주문은 합의의 사본이지 현재 정책으로 다시 계산하는 견적이 아니기 때문이다.
- **PD-0023-R11:** 주문의 배송지는 주문 시점의 사본이다. 회원의 주소록이 바뀌거나 주소가 삭제되어도 주문에 남은 값은 변하지 않는다. 근거 미기록.
- **PD-0023-R12:** 주문은 최소 한 줄 이상을 가지며, 각 줄의 수량은 1 이상이다. 근거 미기록.
- **PD-0023-R13:** 요청자 소유가 아닌 주문은 존재하지 않는 주문과 같은 응답으로 거절한다. 근거: 구분하면 어떤 주문 식별자가 존재하는지 알아낼 수 있다.

## 거절하는 시나리오

- 이미 결제된 주문을 다시 결제하는 요청 (R1).
- 결제되지 않은 주문에 배송을 붙이거나 배송 완료로 만드는 요청 (R2, R3).
- 배송이 완료된 주문의 취소 요청 (R4).
- 비원화 상품이 하나라도 포함된 견적 또는 주문 요청 (R5).
- 상품 금액이 49,999원인 주문을 무료배송으로 처리하는 요청 (R6).
- 확인한 견적보다 상품 금액, 배송비 또는 최종 결제 금액이 달라진 주문 요청 (R9).
- 라인이 없거나 수량이 1보다 작은 주문 요청 (R12).
- 다른 회원의 주문 조회 요청 (R13).

## 허용하는 시나리오

- 상품 금액이 정확히 50,000원인 주문은 배송비가 0원이다 (R6).
- 배송비 정책이 바뀌었어도 해당 주문의 상품 금액, 배송비와 최종 결제 금액이 이전 견적과 같으면 주문한다 (R9).
- 주문 접수 뒤 상품 가격이나 무료배송 기준이 바뀌어도 기존 주문과 같은 주문 요청은 접수 당시 금액 구성을 유지한다 (R10).
- 배송을 거치지 않고 결제됨에서 바로 배송 완료로 갈 수 있다 (R3).
- 결제가 끝난 주문도 배송이 완료되기 전이라면 취소된다. 결제와 배송을 되돌리는 방식은 이 정책이 정하지 않는다 (R4).

## 정책이 정하지 않는 것

- 쿠폰이나 할인이 생겼을 때 무료배송 기준을 할인 전후 어느 상품 금액에 적용할지.
- 지역, 배송 속도, 상품 종류나 배송사별로 다른 배송비.
- 세금의 부과와 금액 구성.
- 취소, 반품과 환불 시 배송비를 되돌리는 기준.
- 금액 구성의 저장 방식과 견적 식별 방법.
- API 필드, 화면 배치와 0원 배송비의 표시 문구.
- 주문을 언제까지 보관하는가.

## 고려한 대안

**주문 금액과 무관하게 항상 3,000원을 부과한다 — 채택하지 않음.** 규칙은 단순하지만 상품 금액이 일정 기준을 넘은 주문에 무료배송을 제공하지 못한다.

**우편번호나 지역별 배송비를 부과한다 — 채택하지 않음.** 지역 요율과 주소별 판정 기준이 없는 상태에서 첫 배송비 정책으로 도입하면 고객이 예측하기 어렵다.

**주문 목록에는 최종 결제 금액만 표시한다 — 채택하지 않음.** 상세를 열기 전에는 배송비가 포함된 이유를 확인할 수 없다.

**결제 전에만 금액 구성을 표시한다 — 채택하지 않음.** 결제 뒤에는 배송비가 왜 청구됐는지 주문 내역에서 확인할 수 없다.

## 재검토 조건

- 쿠폰이나 할인으로 상품 금액이 달라질 때.
- 원화 외 통화를 지원할 때.
- 한 주문이 여러 판매자나 여러 배송으로 분리될 때.
- 지역, 배송 속도, 상품 종류 또는 배송사별 요율을 도입할 때.
- 취소, 반품 또는 환불에서 배송비 반환 기준을 정할 때.
- 배송 완료가 자동으로 기록되기 시작할 때.
