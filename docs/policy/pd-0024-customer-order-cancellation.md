# PD-0024: 고객 주문 취소

- **날짜:** 2026-09-19
- **대체:** 해당 없음
- **대체됨:** 해당 없음

## 배경과 문제

결제가 끝난 주문에는 배송, 확정된 결제와 차감된 재고가 함께 존재하지만 고객이 이를 하나의 취소로 되돌릴 수 없다. 각 서비스의 되돌리기 기능을 따로 호출하면 일부만 끝난 상태가 남을 수 있고, 출고와 취소가 겹쳤을 때 어느 요청을 받아들일지도 분명하지 않다.

고객 취소는 주문 도메인이 기술적으로 취소 상태로 전이할 수 있는 범위보다 좁다. 출고 뒤의 회수는 취소가 아니라 반품으로 다뤄야 하며, 처리 중단이나 반복 요청 때문에 환불과 재고 복원이 중복되어서도 안 된다.

## 목표

고객은 성공한 자신의 주문 전체를 출고 전에 한 번 취소할 수 있다. 받아들인 취소는 배송을 멈추고 결제 대금과 판매 가능 재고를 모두 되돌린 뒤 하나의 완료 결과로 끝난다.

## 정책

- **PD-0024-R1:** 고객은 체크아웃이 성공한 자신의 주문 전체만 취소할 수 있다. 처리 중이거나 확인 중이거나 실패한 체크아웃은 고객 취소 대상이 아니다. 근거: 체크아웃 복구와 고객 취소가 같은 결제·배송·재고를 동시에 바꾸지 않게 하기 위해서다.
- **PD-0024-R2:** 고객 취소는 배송이 준비 상태일 때만 허용한다. 배송이 출고되었거나 완료되었으면 거절한다. 근거: 출고 뒤에는 회수와 검수가 필요한 반품 절차가 필요하기 때문이다.
- **PD-0024-R3:** 출고와 취소가 겹치면 배송에 먼저 확정된 전이가 이긴다. 배송 취소가 먼저 확정되면 이후 출고할 수 없고, 출고가 먼저 확정되면 고객 취소를 받아들이지 않는다. 근거: 서로 다른 서비스의 요청 시각이 아니라 물류의 단일 상태 전이로 경계를 판정해야 하기 때문이다.
- **PD-0024-R4:** 배송 취소가 확정된 고객 취소는 철회하거나 원래 주문으로 되돌리지 않고 나머지 처리를 끝까지 완료한다. 근거: 이미 배송을 중단한 뒤 주문을 되살리면 결제·재고·배송의 사실이 다시 어긋날 수 있기 때문이다.
- **PD-0024-R5:** 고객 취소는 상품 금액과 배송비를 합친 최종 결제 금액 전액을 환불한다. 부분 환불이나 배송비 유보는 허용하지 않는다. 근거: 출고 전 전체 취소에는 제공된 배송 서비스가 없고 고객이 주문 전체를 철회했기 때문이다.
- **PD-0024-R6:** 고객 취소는 주문의 모든 상품 수량을 판매 가능한 재고로 정확히 한 번 복원한다. 근거: 판매가 취소된 수량이 계속 차감되어 있거나 반복 처리로 중복 증가해서는 안 되기 때문이다.
- **PD-0024-R7:** 취소의 배송 중단, 환불과 재고 복원은 처리 중단과 반복 요청이 있어도 완료된 단계를 중복 적용하지 않고 하나의 결과로 수렴해야 한다. 근거: 외부 호출의 응답을 잃거나 실행자가 중단되는 것은 정상적인 복구 대상이기 때문이다.
- **PD-0024-R8:** 한 주문에는 고객 취소가 하나만 존재한다. 같은 주문의 반복 요청은 새 취소를 만들지 않고 기존 진행 상태나 완료 결과를 반환한다. 근거: 취소 대상 주문 자체가 업무의 고유 식별자이기 때문이다.
- **PD-0024-R9:** 고객에게는 취소 처리 중, 취소 확인 중, 취소 완료를 구분해 보여준다. 배송 중단, 전액 환불과 재고 복원이 모두 끝나기 전에는 취소 완료로 표시하지 않는다. 근거: 실제로 돈이나 재고가 돌아오지 않았는데 완료로 오해하게 해서는 안 되기 때문이다.
- **PD-0024-R10:** 외부 처리 결과를 안전하게 판단할 수 없으면 성공이나 실패로 추정하지 않고 현재 상태를 확인한다. 자동 판단이 위험하면 고객에게 취소 확인 중으로 보이고 운영 확인 대상으로 남는다. 근거: 추측으로 재실행하면 이중 환불이나 재고 중복 복원이 생길 수 있기 때문이다.
- **PD-0024-R11:** 고객 취소 사유는 자유 입력을 받지 않고 고객 요청이라는 정형화된 사유로 기록한다. 근거: 첫 취소 흐름에는 분류되지 않은 개인정보성 문장을 수집할 필요가 없기 때문이다.
- **PD-0024-R12:** 취소 요청과 취소 완료는 고객의 주문 진행 이력에서 구분한다. 완료 알림은 배송 중단, 전액 환불과 재고 복원이 모두 끝난 뒤 한 번만 만든다. 거절된 요청과 처리 중 상태는 완료 알림을 만들지 않는다. 근거: 진행 중인 요청을 완료로 오해하게 하지 않으면서 고객이 자신이 요청한 사실과 최종 결과를 확인할 수 있어야 하기 때문이다.
- **PD-0024-R13:** 체크아웃 실패와 고객 주문 취소는 서로 다른 사실로 기록하고 고객에게도 다르게 표현한다. 근거: 구매가 성립하지 않은 실패와 성립한 구매를 고객이 철회한 결과는 원인과 후속 의미가 다르기 때문이다.

## 거절하는 시나리오

- 처리 중, 확인 중 또는 실패한 체크아웃의 고객 취소 요청 (R1).
- 다른 회원이 소유한 주문의 취소 요청 (R1).
- 배송이 출고되었거나 완료된 주문의 취소 요청 (R2, R3).
- 상품 일부나 수량 일부만 취소하거나 환불하려는 요청 (R1, R5, R6).
- 배송비를 제외하고 상품 금액만 환불하는 처리 (R5).
- 자유 입력 취소 사유를 저장하려는 요청 (R11).

## 허용하는 시나리오

- 성공한 주문의 배송이 준비 상태라면 결제와 재고가 이미 확정되었어도 전체 취소할 수 있다 (R1, R2).
- 같은 취소 요청을 여러 번 보내거나 실행자가 단계 사이에서 중단되어도 기존 진행을 이어간다 (R7, R8).
- 자동 판단이 위험한 취소가 주문 내역에서 사라지지 않고 취소 확인 중으로 남는다 (R9, R10).
- 배송 취소가 먼저 확정된 뒤 환불이나 재고 복원에 장애가 생겨도 취소를 철회하지 않고 복구를 계속한다 (R4, R7).

## 정책이 정하지 않는 것

- 취소 진행 상태를 저장하는 테이블과 단계의 이름.
- 서비스 호출 방식, 임차 시간, 재시도 간격과 배치 크기.
- API 경로, 응답 필드와 화면 배치.
- 환불과 재고 복원을 구현하는 클래스와 메서드.
- 운영 확인 신호의 전달 수단과 수동 재개 절차.

## 고려한 대안

- 배송 완료 전까지 고객 취소를 허용하는 방안은 배송 중 상품의 회수와 검수 없이 주문만 취소될 수 있어 제외했다. 출고 뒤 처리는 반품 정책에서 다룬다.
- 배송비를 환불하지 않는 방안은 출고 전에 배송 서비스가 제공되지 않았는데도 비용을 남기므로 제외했다.
- 처리 중인 체크아웃에도 취소 의사를 받는 방안은 체크아웃 복구와 취소가 같은 결제·배송·재고를 동시에 바꿀 수 있어 제외했다.
- 자유 입력 취소 사유를 받는 방안은 고객 분석에 쓸 수 있지만 첫 취소 흐름에 불필요한 개인정보 수집과 입력 검증을 더하므로 제외했다.

## 재검토 조건

- 출고 뒤 반품·교환·환불을 도입할 때.
- 부분 취소나 부분 환불을 지원할 때.
- 여러 배송 또는 여러 결제로 한 주문을 이행할 때.
- 취소 사유 분석이 필요해 정형화된 사유 선택지를 도입할 때.
- 취소 확인 중 상태가 장시간 반복되어 별도의 고객 지원 약속이 필요할 때.
