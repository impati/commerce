# PD-0026: 주문 생애주기, 배송 투영과 금액 구성

- **날짜:** 2026-09-24
- **대체:** PD-0023
- **대체됨:** 해당 없음

## 배경과 문제

이전 정책은 주문과 배송이 서로 독립적으로 전이되고, 배송이 없어도 주문을 배송 완료로 만들 수 있게 했다. 이 전제에서는 주문과 배송의 결과가 어긋나도 어느 쪽이 물리적 이행의 진실인지 판단할 수 없다.

배송 진행의 정본을 배송으로 정하고도 주문 내역이 배송 서비스의 가용성에 매번 의존하지 않도록, 주문이 어떤 배송 사실을 받아 고객에게 보여주고 어떤 사건으로 생애주기를 바꾸는지 정해야 한다. 기존의 주문 금액·배송비·배송지 사본 규칙은 그대로 유지한다.

## 목표

주문은 결제와 전체 구매 생애주기를 소유하고, 배송은 물리적 이행을 소유한다. 고객은 한 주문에서 확정된 금액과 배송 진행을 계속 확인하며, 두 서비스의 상태가 일시적으로 전달되지 않아도 결국 같은 사실로 수렴한다.

## 정책

- **PD-0026-R1:** 주문은 생성 시점에 결제 전 상태이며, 결제가 매입되면 결제됨으로 넘어간다. 결제 전 상태가 아닌 주문은 다시 결제할 수 없다. 근거: 주문의 성공 경계는 실제 청구가 확정되는 시점이어야 한다.
- **PD-0026-R2:** 결제가 확정된 주문에는 내부 배송이 하나 연결되고 주문은 이행 중이 된다. 이때 택배사나 운송장 번호가 아직 없어도 주문 확정을 막지 않는다. 근거: 택배 접수는 포장 완료 뒤의 운영 업무이며 이미 성립한 구매를 그 업무가 끝날 때까지 미확정으로 둘 이유가 없다.
- **PD-0026-R3:** 물리적 배송 진행의 정본은 배송이다. 주문은 연결된 배송에서 확정된 공통 배송 상태, 택배사·운송장과 고객용 이력을 전달받아 조회용으로 유지하며 임의의 고객 명령으로 배송 결과를 만들지 않는다. 근거: 배송 상태를 두 서비스가 독립적으로 결정하지 않으면서 배송 서비스 장애 중에도 마지막으로 확인된 주문 내역을 보여주기 위해서다.
- **PD-0026-R4:** 연결된 배송의 택배사 배송 완료가 확정되면 주문은 배송 완료가 된다. 배송이 없거나 택배사 배송 완료가 확인되지 않은 주문을 직접 배송 완료로 만들 수 없으며 별도의 고객 구매 확정을 요구하지 않는다. 근거: 직매입 쇼핑몰에서는 택배사의 물리적 전달 결과면 배송 완료를 판정하기에 충분하고 판매자 정산을 위한 구매 확정이 필요하지 않다.
- **PD-0026-R5:** 최종 배송 실패, 반송 중과 반송 완료는 주문의 고객용 배송 상태와 이력에 나타난다. 반송 완료만으로 주문을 취소하거나 결제를 환불하거나 재고를 복원하지 않으며, 후속 처리가 끝나기 전까지 고객에게 반송 결과와 환불 전임을 함께 알린다. 근거: 물건이 돌아온 사실과 검수·금전·재고 처리는 서로 다른 업무다.
- **PD-0026-R6:** 고객 취소는 택배사 집하 전에만 허용하고, 배송 완료 주문은 취소할 수 없다. 취소가 받아들여지면 배송 중단, 전액 환불과 재고 복원을 완료한 뒤 주문을 취소로 확정한다. 근거: 집하 뒤에는 물건 회수가 필요한 반품이며 취소와 같은 절차로 처리할 수 없다.
- **PD-0026-R7:** 상품 금액은 주문 시점의 각 상품 단가와 수량을 곱한 라인 금액의 합이며 모든 금액은 원화여야 한다. 비원화 상품이 포함된 견적과 주문은 거절한다. 근거: 환율이나 통화별 배송비를 정하지 않은 상태에서 서로 다른 통화의 수치를 청구 금액으로 합치지 않기 위해서다.
- **PD-0026-R8:** 한 주문의 상품 금액이 50,000원 이상이면 배송비는 0원이고, 50,000원 미만이면 배송비는 3,000원이다. 무료배송 기준에는 배송비 자체를 포함하지 않는다. 근거: 첫 배송비 정책은 주문 단위의 예측 가능한 단일 기준으로 시작한다.
- **PD-0026-R9:** 최종 결제 금액은 상품 금액과 배송비의 합이며, 견적과 접수된 주문은 같은 세 금액을 사용한다. 근거: 고객이 확인한 구성과 실제 청구 금액이 달라지지 않아야 한다.
- **PD-0026-R10:** 장바구니, 결제 결과, 주문 목록과 주문 상세에는 상품 금액, 배송비와 최종 결제 금액이 구분되어 나타난다. 근거: 고객이 결제 전후 어느 주문 화면에서도 배송비가 포함된 이유를 확인할 수 있어야 한다.
- **PD-0026-R11:** 견적 확인 뒤 상품 내용이나 금액 정책의 적용 결과가 달라져 세 금액 중 하나라도 바뀌면 주문을 접수하지 않고 새 견적 확인을 요구한다. 정책이 바뀌어도 해당 주문의 금액 구성이 같다면 새 확인을 요구하지 않는다. 근거: 고객이 확인하지 않은 금액은 청구하지 않되 결과가 같은 내부 정책 변경으로 구매를 불필요하게 막지 않기 위해서다.
- **PD-0026-R12:** 접수된 주문은 상품 금액, 배송비와 최종 결제 금액을 주문 시점의 값으로 유지한다. 이후 상품 가격이나 배송비 정책이 바뀌어도 기존 주문과 같은 주문 요청의 결과는 바뀌지 않는다. 근거: 주문은 합의의 사본이지 현재 정책으로 다시 계산하는 견적이 아니기 때문이다.
- **PD-0026-R13:** 주문의 배송지는 주문 시점의 사본이다. 회원의 주소록이 바뀌거나 주소가 삭제되어도 주문에 남은 값은 변하지 않는다. 근거: 이미 성립한 구매의 배송 대상이 주소록의 후속 변경으로 달라져서는 안 된다.
- **PD-0026-R14:** 주문은 최소 한 줄 이상을 가지며 각 줄의 수량은 1 이상이다. 근거: 상품이 없거나 수량이 없는 주문은 금액과 이행 대상을 확정할 수 없다.
- **PD-0026-R15:** 요청자 소유가 아닌 주문은 존재하지 않는 주문과 같은 응답으로 거절한다. 근거: 주문 식별자를 아는 것만으로 주문의 존재나 상품, 금액과 배송 진행을 알아낼 수 없어야 한다.

## 거절하는 시나리오

- 이미 결제된 주문을 다시 결제하는 요청 (R1).
- 배송이 없거나 배송 완료 사건이 없는 주문을 직접 배송 완료로 만드는 요청 (R4).
- 택배사 집하 뒤 고객 취소를 시작하는 요청 (R6).
- 비원화 상품이 하나라도 포함된 견적 또는 주문 요청 (R7).
- 상품 금액이 49,999원인 주문을 무료배송으로 처리하는 요청 (R8).
- 확인한 견적보다 상품 금액, 배송비 또는 최종 결제 금액이 달라진 주문 요청 (R11).
- 라인이 없거나 수량이 1보다 작은 주문 요청 (R14).
- 다른 회원의 주문 조회 요청 (R15).

## 허용하는 시나리오

- 운송장이 아직 발급되지 않았어도 결제와 내부 배송이 확정된 주문은 이행 중이다 (R2).
- 배송 사건 전달이 늦으면 마지막으로 확인한 배송 상태를 보여주고, 사건이 도착하면 같은 주문 내역이 새 상태로 수렴한다 (R3).
- 배송 실패와 반송 완료가 표시되지만 환불이 아직 시작되지 않은 주문이 존재한다 (R5).
- 상품 금액이 정확히 50,000원인 주문은 배송비가 0원이다 (R8).
- 주문 접수 뒤 상품 가격이나 배송비 정책이 바뀌어도 기존 주문과 같은 주문 요청은 접수 당시 금액 구성을 유지한다 (R12).

## 정책이 정하지 않는 것

- 배송 사건의 전송 수단, 전달 지연 상한, 저장 구조와 재처리 방식.
- 반송 뒤 검수, 환불과 재고 복원 규칙.
- 쿠폰이나 할인이 생겼을 때 무료배송 기준을 할인 전후 어느 금액에 적용할지.
- 지역, 배송 속도, 상품 종류나 택배사별로 다른 배송비.
- 세금의 부과와 금액 구성.
- API 필드, 화면 배치와 고객 안내 문구의 구체적인 표현.
- 주문과 진행 이력의 보관 기간.

## 고려한 대안

**주문과 배송이 각자 배송 완료를 결정한다 — 채택하지 않음.** 두 상태가 어긋났을 때 어느 쪽이 실제 물류 결과인지 판단할 수 없다.

**주문 조회 때마다 배송을 실시간 조회한다 — 채택하지 않음.** 중복 저장은 줄지만 배송 서비스 장애가 기존 주문 내역까지 보이지 않게 만든다.

**배송 없이 결제된 주문을 직접 완료할 수 있게 한다 — 채택하지 않음.** 현재 모든 성공 주문에 배송이 하나 존재하며 우회 경로는 택배사 사건을 정본으로 둔 결정을 무너뜨린다.

**택배사 배송 완료 뒤 고객 구매 확정을 기다린다 — 채택하지 않음.** 판매자 정산이 없는 직매입 모델에서는 거래를 한 단계 더 열어 둘 가치가 없다.

**반송 완료와 동시에 주문을 취소하고 환불한다 — 채택하지 않음.** 회수 물건의 검수와 환불·재고 복원 정책이 정해지지 않은 상태에서 물류 사건만으로 금전 결과를 확정할 수 없다.

## 재검토 조건

- 여러 판매자나 여러 배송으로 한 주문을 이행할 때.
- 디지털 상품이나 매장 수령처럼 배송이 없는 주문을 지원할 때.
- 구매 확정과 판매자 정산을 도입할 때.
- 반송 뒤 환불과 재고 복원 정책을 도입할 때.
- 쿠폰, 할인, 외화, 세금 또는 지역·배송 방식별 요금을 도입할 때.
